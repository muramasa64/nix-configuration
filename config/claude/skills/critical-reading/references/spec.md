# 仕様書・設計書・要件定義のチェックリスト

仕様書では「主張が真か」よりも「一意に解釈でき、矛盾がなく、実装・検証できるか」を評価する。手順7の評価では、主張の代わりに要件や仕様項目を対象にしてよい。

## 版と範囲
- 文書の版、改訂履歴、承認状態(ドラフトか確定版か)を確認する。
- 対象範囲と対象外が明記されているか。
- 参照している外部仕様や規格の版が特定されているか。

## 曖昧さ
- 「適切に」「速やかに」「十分な」「など」のように、解釈が分かれる表現がないか。
- 必須と任意の区別があるか(MUST / SHOULD / MAY、「しなければならない」「することが望ましい」)。
- 用語が定義されているか。同じ概念に別の用語、別の概念に同じ用語を使っていないか。
- 数値要件に単位、測定条件、許容範囲が付いているか。

## 整合性
- 文書内で矛盾する記述がないか(本文と図表、章と章)。
- 上位文書(要件定義、契約、規格)と矛盾していないか。
- 図、表、例が本文の定義と一致しているか。

## 網羅性
- 正常系だけでなく、異常系、境界値、タイムアウト、同時実行を扱っているか。
- 非機能要件(性能、可用性、セキュリティ、運用、移行)が書かれているか。
- 状態遷移やデータの生成から廃棄までのライフサイクルに抜けがないか。
- 権限、認証、監査ログなど、セキュリティ上の前提が明記されているか。

## 検証可能性
- 各要件について、満たしたかどうかを判定する方法(テスト、受け入れ基準)が考えられるか。
- 未決事項(TBD)が残っていないか。残っている場合、期限と担当が決まっているか。
